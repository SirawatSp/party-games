## งานที่ตรวจแล้ว

- ชื่อและชื่อเรียกอื่น 254 ค่าในคลังเดิมไม่ชนข้ามรายการ ภาพต้นทางไม่ซ้ำตามข้อมูลที่เก็บไว้
- ภาพอาหารเดิม 40 ไฟล์เปิดได้ ภาพสอดคล้องกับเฉลย เครดิตตรงข้อมูลในคลังและอยู่ในรายการแคชครบ
- ตัวตรวจเพิ่มการจับชื่อ/ชื่อเรียกอื่นซ้ำข้ามหมวด ภาพและ `sourceFile` ซ้ำ URL สิทธิ์ผิดรูปแบบ และภาพอาหาร/เครดิต/แคชไม่ครบ โดยไม่เพิ่ม dependency
- ชุด Playwright อ่านจำนวนจากไฟล์คลังจริง เลิกล็อกยอด 40/120 และเพิ่มการข้ามภาพเสียกับการเล่นอาหารหลังตัดเครือข่ายผ่าน service worker จริง
- แก้ยอดเก่า 30 รูปในคู่มือเป็น 120 และบันทึกเป้าหมาย 480 รูป
- รัน `node scripts/check-content.js` ผ่าน 27 คลัง ไม่มี ERROR อ่าน REVIEW เดิม 109 รายการครบ ไม่มีของ `picturereveal`
- รัน `node scripts/ship.js` ผ่าน สร้างจำนวนหน้าแรกใหม่ ซึ่งยังเป็น 120 รูป และเลื่อน `CACHE_VERSION` จาก `party-games-v118` เป็น `party-games-v119`
- กรณีทดสอบตัวตรวจด้วยข้อมูลผิดในสำเนาชั่วคราวผ่าน 12/12 ไม่แก้ข้อมูลใช้งานจริง

ผล Playwright/Chromium รอบสุดท้ายเฉพาะภาพในเครื่องผ่าน 62/62 รวมปุ่มเปลี่ยนทั้งสามหมวด เฉลยคนดำเนินเกม ลองใหม่/ข้ามภาพเสีย และเปิดหน้าเกมหลังตัดเครือข่ายโดย service worker เสิร์ฟภาพอาหารครบ 40/40 ใช้คำสั่ง `PICTURE_LOCAL_ONLY=1 CHROMIUM_PATH=/usr/bin/chromium node scripts/test-picture-reveal.js` ไม่ใช้ภาพจำลองแทนภาพจริง ผลเต็มและภาพหน้าจอมือถือ/คอมพิวเตอร์เก็บในโฟลเดอร์ `evidence/` ของชุดส่งต่อ การทดสอบครบทุกภาพออนไลน์ยังติดเครือข่ายตั้งแต่โหลดภาพเริ่มเกมและไม่นับว่าผ่านจากการทดสอบเฉพาะไฟล์ในเครื่อง

## ข้อจำกัดและขั้นที่ค้าง

เครือข่าย Cloud อยู่ในโหมด restricted และตอบ `CONNECT tunnel failed, response 403` ต่อ `sirawatsp.github.io`, `en.wikipedia.org` และ `upload.wikimedia.org` ไม่ได้แก้นโยบายหรือเลี่ยง proxy ต้องเพิ่มโดเมนที่ต้องใช้ผ่านการตั้งค่าเครือข่าย Cloud ก่อนทำขั้นที่พึ่งพาแหล่งภาพ ใช้ `commons.wikimedia.org` สำหรับหน้าเครดิตอาหารด้วย และตรวจ host ของภาพสำรองแต่ละรายการตามจริง

ภาพหนัง/การ์ตูนเดิม 76 จาก 80 รายการยังมีข้อความผู้สร้างแบบรวม ต้องตรวจชื่อผู้สร้างกับหน้าต้นทางเมื่อเครือข่ายพร้อม รอบนี้ยืนยันได้ว่ามีฟิลด์และลิงก์ ไม่ได้ยืนยันเครดิตเฉพาะรายซ้ำจากแหล่งออนไลน์

1. ดึง `master` ล่าสุดจาก GitHub และเทียบกับฐานที่ระบุไว้ก่อนเปิดงานต่อ ค้นประวัติแชตที่ยังอ่านไม่ได้ หากกู้ชุดค้างได้ให้เทียบ diff และไฟล์จริงก่อนใช้
2. ตรวจชื่อ/แฟรนไชส์และเลือกภาพจริงจากรายการเสนอหรือชุดที่กู้ได้ ตรวจผู้สร้าง สิทธิ์ และลิงก์สำรอง ห้ามเดา URL หรือข้อมูลสิทธิ์
3. ดาวน์โหลดอาหารเพิ่ม 15 ไฟล์ ตรวจภาพให้ตรงเฉลยและเพิ่มเครดิตกับ `PRECACHE_URLS` ให้ครบ ส่วนโปสเตอร์ใช้ลิงก์ออนไลน์ตามแนวทาง repo
4. เตรียม JSON ที่มีฟิลด์ครบ แล้วใช้ `node scripts/add-entries.js picturereveal new.json --dry` ก่อนรับเข้า ตรวจรายการใหม่ด้วย `node scripts/check-content.js picturereveal --new 45`
5. รัน Playwright ครบทุกหมวดและภาพจริง ใช้ `CHROMIUM_PATH=/usr/bin/chromium node scripts/test-picture-reveal.js` รัน `node scripts/check-content.js` และ `node scripts/ship.js` หลังเนื้อหาพร้อม นับยอดใหม่และสร้าง ZIP/diff ที่รวมไฟล์ภาพใหม่จริงทั้งหมด
6. เก็บให้ตรวจใน Cloud ต่อไป เมื่อเจ้าของสั่ง deploy เท่านั้นจึงดึง `master` ล่าสุดอีกครั้ง ทำตามกติกา repo แล้วตรวจทั้ง GitHub Pages workflow และยอดจากเว็บจริง เปิด PR เฉพาะเมื่อเจ้าของสั่ง

ชุดส่งต่อรวม snapshot เว็บทั้งหมดพร้อมภาพอาหารเดิม 40 ไฟล์, diff เทียบฐาน, รายการเสนอ 45 ชื่อ, หลักฐานการตรวจและภาพหน้าจอ ไม่มีไฟล์ภาพใหม่ในรอบนี้
